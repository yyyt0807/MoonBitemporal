# 迟到更正的通用应用场景

以下示例是可运行、有断言的内存集成工作流，展示库接口如何用于实际需求。它们不包含线上服务、数据库和完整业务系统。

## 1. 价格/费率更正后的订单复核

- 用户：电商、订阅、物流费率、内部费用计算工具的开发者。
- 输入：最初录入每单位 1000 分的价格；四张发票分别发生于有效时间 35、50、30、45，均按知识时间 10 的事实开出，每张三件。
- 后续更正：知识时间 20 才知道有效时间 `[30,45)` 应为 950 分。
- 过程：开票时 `capture_decision` 保存采用的价格；更正后 `audit_decisions` 保留全部四条复核结果，应用筛选 `needs_recompute` 并重新计算。
- 结果：仅有效时间 30、35 的两张发票需要各调整 -150 分，右端 45 和外部点 50 不变；旧发票价格仍可复现。
- 价值：把区间更正映射为具体业务记录，调用者不必重新计算全部业务记录。多事实决策需分别保存依赖并由应用合并。

```sh
moon run examples/decision_review --target wasm-gc
```

## 2. 权限/策略的事后复核与来源审查

- 用户：SaaS 权限、组织策略、路由规则、配置平台开发者。
- 输入：一个从有效时间 0 起允许访问的策略；记录发生于时间 5、25 的两个请求及其当时采用的事实。
- 后续更正：撤回 `[0,10)` 的规则，同时从 20 起重新发布内容相同的 `allow`。
- 过程：复核区分两类结果：时间 5 的事实被撤回，时间 25 的策略值未变但来源修订换了。
- 结果：前者 `needs_recompute == true`，后者仅 `provenance_changed == true`；应用按自己的规则处理访问复核与来源审查。
- 价值：避免把所有重新发布都误报成权限结果变化，又保留来源证据。库不执行认证、角色判断或自动撤销访问。

```sh
moon run examples/access_review --target wasm-gc
```

## 3. 校准/主数据更正的区间来源解释

- 用户：传感器数据处理、质量分析、产品主数据、汇率/税率参考数据开发者。
- 输入：校准因子在 `[0,10)` 为 `gain=1.1`，`[10,20)` 已撤回，`[20,30)` 从未记录。
- 后续更正：重新发布整个 `[0,30)` 的 `gain=1.1`。
- 过程：`supersession_fragments` 输出三个区间，携带完整旧赢家/撤回/空白以及新修订。
- 结果：第一段数值不变但来源改变，后两段由撤回/未记录变成有值；示例导出三条 JSON 证据，并验证旧知识视图仍然成立。
- 价值：解释“此次更正覆盖了什么、过去依据是什么”，适用于对区间数据进行复核、重处理和来源追踪。计算校准后的数值由应用负责。

```sh
moon run examples/correction_evidence --target wasm-gc
```

## 已有可复用工作流

`examples/pricing`、`access`、`calibration`、`rollout` 展示旧认知回放、修订影响和配置差异；`maintenance` 展示完整批次分页同步和多键共同覆盖。它们与新增能力共用同一双时间账本，无需将库绑定到任何特定业务类型。

## 集成约束

应用应统一时间单位并可信地分配递增知识时间；业务 ID 可对应订单、请求或测量批次。`DecisionEvidence` 当前保存在内存；需要跨进程复核时，应持久化业务查询参数及账本档案，重新构建证据。JSON 复核结果只用于导出，当前没有证据导入 API。来源检查仅核对对应历史查询事实，不证明整个账本同源；需要全档案同源校验时配合 `reconcile` 或可信归档。证据没有签名和密码学抗篡改保证。
